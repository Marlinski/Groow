Skills

A skill is documentation and an executable together, in the format the Agent Skills specification describes: a directory with a SKILL.md in it, giving a name, a description of when to reach for it, and a page saying how.

In the prompt
One line each. The name and the description, so it knows the thing exists and when it is worth using. Nothing more, ever.
On demand
The page. groow skill read <name> pulls the rest into context, when it has decided it needs it.
To run
A command. The scripts in the skill go on its path, so it is used through the shell like anything else, with an exit status it can learn from.
Over time
Less needed. A skill practised often enough ends up in the weights, and the page stops being read. That is the point.

Why this format and not a tool

Groow's competence is supposed to end up in its weights. A skill is the opposite kind of memory: precise, written down, and looked up. Keeping the two apart is what makes them useful together, and it is why only a line of each skill is ever in the prompt. A skill it wrote yesterday is not in its weights yet and must be findable; a skill it has used a hundred times should cost nothing to keep.

That is what progressive disclosure buys here. The alternative, carrying a paragraph about every skill in every prompt, is the accumulate-context approach this project was built to avoid.

What one looks like

news/
  SKILL.md          name, description, and how to use it
  scripts/news      the executable, in any language
  references/       optional: detail it can read when it needs to
  assets/           optional: templates, data
---
name: news
description: Fresh headlines from your own feeds, skipping anything you have
  already been shown. Use when you want to know what has happened in the world.
compatibility: Requires network access
---

# Reading the news

```
news              headlines you have not seen
news --json       the items as records, with links
```
…

The name must be lowercase letters, digits and hyphens, and must match its directory. A skill without a description is refused rather than half-loaded: a skill nobody can find is worse than an error that says so.

The prompt it writes for itself

What Groow sees at the start of every turn is not fixed by the core. The core contributes only the part it may not argue with, its identity and the facts on its certificate. Everything after that is the output of ~/.groowrc, a shell script in its own home, run at the start of each turn.

#!/bin/sh
echo "Today is $(date '+%A %-d %B %Y, %H:%M')."
echo
echo "Skills you have. Each one is a command you run in your shell, not a tool you call."
groow skill list | sed 's/^/- /'

It is the same thing a person does when they tune their shell prompt: put what you want in front of you, take out what you do not read. Groow can put its skills there, the date, what is on its disk, a note about what it is working on, or nothing.

It cannot lock itself out with it. If the script fails, hangs or prints a library, the turn happens anyway and that part of the prompt says what went wrong instead, which is exactly what it needs to fix the file.

Writing one

There is nothing to learn beyond the format. It writes the directory, makes the script executable, and runs it. Its own commands come first on its path, so a skill it writes shadows a shipped one of the same name, and if the command is wrong it finds out the way anyone does: a non-zero exit and a message on standard error, both of which reach the conversation and count towards how the turn felt.

The core itself

Groow cannot edit the core. It is a compiled binary owned by root, and the part of the system that has to be right. What it can do is write a command, run it, see it fail, and fix it, which is the loop that actually matters.
