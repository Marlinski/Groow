Skills

A skill is an executable file in Groow's own bin directory. That is the entire specification. Python, shell, a compiled binary: the kernel runs it, Groow reads what it printed and sees how it exited.

What it is
A file it can run. Anything on its PATH with the execute bit set. No registry, no schema, no plugin interface.
Why
Exit statuses are free lessons. A wrapper tool returns a tidy result. A command returns an error message and a status, which is something to learn from.
Blast radius
Its own process. Nothing is loaded into the core, so a skill that crashes crashes itself and nothing else.
Ownership
Its own. The shipped ones are copied in on a first start and never overwritten once it has changed them.

Writing one

There is nothing to learn. It writes a file, makes it executable, and runs it.

$ cat > ~/.local/bin/tides <<'SH'
#!/bin/sh
# tides : the next high tide, from the public feed
curl -fsS "https://example.org/tides/$1" | head -20
SH
$ chmod +x ~/.local/bin/tides
$ tides brest

Its own directory comes first on the PATH, so a command it writes shadows a shipped one of the same name. If the command is wrong, it finds out the way anyone does: a non-zero exit and a message on standard error, both of which go into the conversation and into what the turn felt like.

What ships

CommandWhat it does
web <url>a page as readable text, with the markup and the menus stripped
newsheadlines it has not seen, from the feeds listed in its own state
tictactoeplays itself, and logs each move with its reward
arithmeticdrills mental arithmetic, and logs each answer with its reward

The last two are how it practises rather than converses. They write decisions to the activity log, which the learning passes turn into policy samples. They talk to the brain directly, not through the core, because a game is background work and must never come before a person.

The home it lives in

/home/groow
  .local/bin/        its own commands, on its PATH, writable by it
  workspace/         somewhere to work, writable by it
  .nix-profile/      tools it installs for itself, no root needed
  state/             the core's, readable by it and not writable
    main/            the conversation
    recipes/         its manual, which it may rewrite
    skills/          drafts and anything it keeps

Inside the sandbox the split is real: the core runs as root and state/ is not writable by the mind, so it cannot edit the conversation, the questions it has asked, or the statistics that say how it is doing. Everything above that line is its own. Outside the sandbox the same directories exist but the separation is a convention, and the core says so when it starts.

The core itself

Groow cannot edit the core. It is a compiled binary owned by root, and the part of the system that has to be right. What it can do is write a command, run it, see it fail, and fix it, which is the loop that actually matters.
