The nervous system

Four parts, three ways of talking, and one rule that explains the shape of all of it: the part that owns a thing is the only part that touches it. The core owns the state, the brain owns the GPU, and the mind owns nothing at all.

IThe socket

A Unix socket in the state directory, carrying newline-delimited JSON frames. Everything between the core and anything that is not the brain goes down it: the mind claiming its turn, the messages it writes, the events it sends up, and a window watching all of it.

It is one connection per process and it carries every kind of traffic at once, which buys three things. The core learns the instant a turn process dies, because the socket closes. It can cancel a turn by closing its own end. And a turn that is generating can still be told something, because a request in flight does not occupy the connection.

Authority comes from the kernel here, not from the conversation. The socket carries the peer's real user id, so the core knows whether it is talking to its owner, to the mind, or to a window before it has read a byte. Nothing a caller says about itself is used to grant anything.

{"req": {"id":7, "op":"turn.claim", "arg":{}}}
{"rep": {"id":7, "ok":{"turn":"01J…","window":[…]}}}
{"ev":  {"name":"tool_call", "t":1789.5, "data":{"name":"shell"}}}
{"push":{"name":"turn_end", "data":{…}}}

Every message on every channel is defined once, in nervous_system/proto, and both languages are generated from it. The encoding is canonical protobuf JSON rather than the binary form, so the same shapes are what sit in the conversation on disk and a person can read them with cat.

IIThe loopback

HTTP on a loopback port, answering in newline-delimited JSON so a long piece of work is not silence. Three endpoints, and they are all the same kind of request: generate, train, consolidate. They go into one queue served by one worker, because there is one GPU.

The mind never reaches the brain itself. It asks the core to generate, and the core relays. That indirection is not ceremony: it is why the core can count what the turn cost, know whether it is thinking or waiting on a command of its own, and refuse a turn that is no longer current. The mind has no address for the brain at all.

The exception is a skill playing in the background, which does call the brain directly, at the lowest priority. A game is not a turn and must never come before a person.

POST /generate    {"messages":[…], "tools":[…], "priority":0}
POST /train       {"max_samples":8}
POST /consolidate {}
GET  /health      {"busy":true, "doing":"train", "waiting":2}

IIIThe files

The largest things never travel. The conversation, the queue of what is waiting, the questions, the alarms and the training samples are files, and the parts that need them open them. The hippocampus appends samples and the brain reads them from a cursor; neither sends the other a dataset.

This is what makes the privilege split possible. Root owns those files and the mind can read them and not write them, which is a stronger statement than any protocol could make: there is no message it could send that would edit its own history, because editing is not something that happens by message.

The reflexes

Some things happen without the mind being involved at all, which is the point of putting them in the core rather than in a tool. An alarm comes due and becomes a signal. A question nobody answered expires and is charged for. A turn whose process died is released and its message put back. A turn that keeps failing is waited out and eventually set down with a line in the conversation. None of these are decisions the mind makes, and none of them can be refused by it.

Why it is not one process

It could be, and it would be simpler. Three things keep it apart:

  • The mind runs as a different user from the core, which is the only reason it cannot write its own history. That needs a process boundary.
  • A turn that goes wrong should take down a turn, not the creature. A process that holds nothing can be killed and restarted with no state to repair.
  • The GPU can hold one copy of the weights, so everything that touches them lives in one process. Training in a second one was tried, and it ran the GPU out of memory while the first went on answering.

What that costs is this page: three ways of talking instead of one. It seems a fair trade for a mind that cannot rewrite what it said.
