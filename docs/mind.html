Mind

One conscious thread over a priority queue of signals, and the inner thoughts it can spawn, watch, pause, resume and kill. The thread is linear because consciousness is; the GPU underneath is not.

The main thought

The main thought is a single rolling conversation (one Harness, priority 0). It is the only thing that speaks to the person or to the mentor. It consumes signals from a mailbox on disk (state/mailbox/) in priority order and does nothing between them; inner thoughts run on their own and reach it only through that mailbox. Every message of its conversation is journalled to state/main/ as it happens, and the window is rebuilt from the journal after a reboot.

PrioritySignalFramed to the model as
0 USERa human typedthe message itself
1 FOCUSa thought called focus() or finished[inner thought a1b2 says] … / [inner thought a1b2 finished] …
2 REMINDERevery N steps of a running thought[reminder, no reply needed] thought a1b2 is at step 6/12: … You may read_thought it, pause it, or ignore this.
3 IDLEnobody spoke for sense_idle_minutesthe curiosity impulse (read the news)
4 HOUSEKEEPINGa night is duehandled by the loop, not the model

Reminders never pile up (a new one replaces a queued one) and are skipped when something more concrete is right behind them. Slash commands are USER signals executed by the loop itself. After any signal, if a night is due and nothing urgent is queued, the mind pauses all thoughts and sleeps.

Inner thoughts

An inner thought is a separate conversation history driven by its own harness in its own asyncio task, with a restricted toolset (it can read, learn, memorise, play, recall; it cannot talk to anyone, ask the mentor or rewrite the identity). A step is one harness turn: the thought is prompted to continue toward its goal, may call tools, and its trace grows. Concurrent thoughts are batched into one forward pass by the generation server and preempted per token when the person speaks.

stateDiagram-v2
  [*] --> running : think(goal, max_steps)
  running --> paused : pause_thought / sleep / session end
  paused --> running : resume_thought
  running --> done : finish(summary) or budget exhausted
  running --> killed : kill_thought / crash
  paused --> killed : kill_thought
  done --> [*]
  killed --> [*]

What a thought can do to the main thought

From insideEffect
focus(message)a FOCUS signal; main reads it as "[inner thought … says]" and decides whether to tell the person
finish(summary)status done, a FOCUS signal with the summary
every thought_reminder_every stepsa REMINDER signal, so main always knows something is running
budget exhaustedstatus done, summary is its last text
crashstatus killed, the error reported as a FOCUS signal

What the main thought can do to a thought

think spawns. Everything else is in the shell: groow thoughts lists, groow thought read|pause|resume|kill <id> manages, and each trace is a file in state/thoughts/. At most max_thoughts run at once. Thoughts survive restarts: on exit running thoughts are paused, on start the main thought is reminded of them.

The clock

Three things wake the mind on their own: a housekeeping tick every few seconds (idle naps, due alarms), a curiosity impulse after sense_idle_minutes of silence, and a night when enough learning steps or enough hours have passed. Everything else is an alarm Groow sets for itself, through its clock skill (a file in state/skills/ it can read and improve):

remind "check the deploy"   --in 30m
remind "read the news"      --every 3h
remind "sum up the day"     --every "daily 22:00"
schedule                    # what is set, and when each fires next
schedule cancel a1b2c3

Alarms are a file in the home (state/schedule.json), so they survive a reboot and Groow can read them like anything else. When one fires it arrives in the mailbox at reminder priority and is framed as "[an alarm you set earlier] …": a message to the conscious thread, never code that runs by itself. A repeat reschedules itself as it fires; a one-shot is removed.

Recall: every trace is readable

Every message of the main conversation is in state/main/*.jsonl; every thought step is an episode of kind thought:<id> in state/episodes.jsonl and a trace in state/thoughts/; every lesson is filed with its source in state/lessons.jsonl. Groow rereads them with grep in its shell. This is the diary the mind can reread; the weights are what it became.

A minute in the life

sequenceDiagram
  participant P as person
  participant M as main thought
  participant T as thought a1b2
  participant G as gen server
  P->>M: "find out what happened in Nigeria this week"
  M->>T: think(goal, 4 steps)
  M-->>P: "started, I will tell you"
  T->>G: step 1 (batched, prio 2)
  P->>M: "quick: 23*19?"
  G-->>T: preempted, requeued
  M->>G: prio 0, streaming
  M-->>P: "437"
  G-->>T: step 1 resumes
  T->>T: shell groow news, read, learn
  T->>M: focus("48 dead, methanol. learned, source Guardian 18 Sep")
  M-->>P: relays the finding
  T->>M: finish(summary)

Design choices worth knowing: thoughts do not passive-learn on their own monologue by default (learn_from_thoughts: false), because inner speech is the most self-distilling text there is. They do change weights through the learning tools they call, which is the point.
